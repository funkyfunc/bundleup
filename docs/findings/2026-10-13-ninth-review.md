# Findings 2026-10-13: the ninth independent review (Pass 1), and what was done about it

Run by a fresh subagent with [the review brief](review-brief.md) after releasing `0.1.0` to PyPI.
The reviewer inspected all 26 modules in `src/bundleup/`, `tests/`, and `docs/`, focusing on
subtle runtime/build edge cases, determinism, `0.1.0` additions (`_verify.py`, `_exe.py`,
`_audit.py`, `_uv.py`, `_cli.py`), and performance bottlenecks.

## Findings and verdicts

| # | Finding | Verdict | Done |
|---|---|---|---|
| 1 | **Bytecode compilation ignored `PYTHONHASHSEED=0`:** `_bytecode.py:92` and `_outputs.py:130` invoked the compiler subprocess with `[python, "-I", ...]`, and in CPython `-I` implies `-E` (ignore `PYTHON*` environment variables), so `PYTHONHASHSEED=0` in `COMPILE_ENV` was ignored and frozen `frozenset` constants varied across runs | Agree (real determinism bug) | Replaced `-I` with `-s -S` and `compile_env()` (which strips host `PYTHON*` variables while keeping `PYTHONHASHSEED="0"`), bumped `_bytecode.FORMAT` to `"v3"`, and added `-s` + `compile_env()` to `_exe.py:precompiled()` too. Tested |
| 2 | **`--format exe` leaked host `PYTHONUSERBASE` / user site-packages / `PYTHONSTARTUP`:** `_exe.py:124` set `PYTHONPATH=""` in the scie lift's `boot.commands`, which prevented `.pyz`'s `runs_bundle_code()` from seeing a leaked `PYTHONPATH`, but did not set `PYTHONNOUSERSITE="1"` or clear `PYTHONUSERBASE` and `PYTHONSTARTUP` | Agree | Added `PYTHONNOUSERSITE="1"`, `PYTHONUSERBASE=None`, and `PYTHONSTARTUP=None` to the scie lift env in `_exe.py` |
| 3 | **Symlinked `--split` and `--format py` bundles failed:** `_loader.py:72` set `_ARCHIVE = os.path.abspath(__file__)` without resolving symlinks, so a symlink in `/usr/local/bin/app` pointing to a `--split` bundle looked for `app.parts` in `/usr/local/bin/`, and `sys.path[0]` comparison missed the real archive directory | Agree | Changed `_ARCHIVE` in `_loader.py` to `os.path.realpath(os.path.abspath(__file__))`. Tested |
| 4 | **`runs_bundle_code()` in `_runtime.py` missed symlinked cache/script paths, `.pth` sub-directories, compiled top-level extensions, and stdlib runners (`-m unittest`):** `_same` compared `normcase(abspath(p))` without `realpath`, `runs_bundle_code` only checked `payload` root for `-m`, only checked `.py` files or packages, and skipped stdlib test/debug runners | Agree | Updated `_same` to check both `abspath` and `realpath`; checked `ENV_PATHS` (`.pth` folders), `ENV_SCRIPTS`, top-level `.so`/`.pyd` extensions, and `STDLIB_RUNNERS` (`unittest`, `doctest`, `pdb`, `cProfile`, `profile`, `timeit`, `trace`) in `_runtime.py` |
| 5 | **`--entry python` omitted `""` from `sys.path[0]` for `-m` and interactive REPL:** `_loader.py:_run_python` removed `_ARCHIVE` from `sys.path` without inserting `""` (or `os.getcwd()` for `-m`), breaking imports from the current working directory | Agree | Inserted `os.getcwd()` for `-m` and `""` for `-c`/stdin/REPL in `_loader.py:_run_python` |
| 6 | **`_is_exe` in `_verify.py` misclassified `.pyz` files with shebangs > 64 bytes (e.g. Nix store):** `header_offset > 64` fired on long `#!` lines and reported `"corrupted: executable trailer can't be read"` | Agree | Guarded `header_offset > 64` with `not head.startswith(b"#!")` in `_verify.py:_is_exe`. Tested |
| 7 | **`_check_dir` and `_check_cache` in `_verify.py` used slow `rglob("*")` + `relative_to()`, ignored symlinks, and crashed on `PermissionError`:** unreadable files raised unhandled `PermissionError` instead of reporting a problem | Agree | Added `_walk_dir` using `os.walk(..., followlinks=False)`, flagging symlinks and catching `OSError` in `_check_dir` and `_check_cache`; guarded `_check_bundle` for zipped `dir` manifests. Tested |
| 8 | **`_join_smoke` in `_cli.py` swallowed `--help` and didn't track value-taking options or `--`:** `bundleup build --smoke --help` built and ran the bundle instead of printing CLI help; `bundleup build --entry --smoke --strict` treated `--smoke` as the flag | Agree | Treated `-h`/`--help`/`--smoke` as build options, skipped value-taking option pairs (`takes_value`) and stopped at `--` in `_join_smoke`; omitted `unpacked copy: not unpacked on this machine` when verifying a `dir` bundle. Tested |
| 9 | **Warm builds always spawned 2 Python subprocesses (`_bytecode.py` and `_outputs.py`):** `_bytecode.precompile` only cached distributions with a `RECORD`, so `__bundleup__/*`, PEP 723 scripts, and folder apps recompiled on every build, and `__main__.pyc` was never cached; `_lock_packages` re-parsed `Marker(marker)` 72× per build; `find_uv()` ran `uv --version` on every call; multi-target builds rebuilt local packages N times | Agree | Added `_extra_distribution` in `_bytecode.py` and `_compile_loader` cache in `_outputs.py` (0 compiler subprocesses on warm builds); cached compiled `Marker` and `canonicalize_name` in `_verify._lock_packages`; cached `_uv_version_ok` in `_uv.py`; refreshed local packages once on `i == 0` in multi-target `build()`. Tested |
| 10 | **Missing `<pkg>/__main__.py` fallback, output path validation, and `check()` with `[tool.bundleup]` target lists:** projects without `[project.scripts]` failed even when `<pkg>/__main__.py` existed; `-o dist/` (existing dir) or `-o script.py` (input script) wasn't caught early; `bundleup check` failed when `[tool.bundleup]` listed multiple platforms | Agree | Added `<pkg>/__main__.py` fallback in `resolve_entry()`, early output path validation in `build()`, and folded `[tool.bundleup]` `more_python_platforms` into `also_platforms` in `check()`; checked all packages in `from_pylock` for editable installs and added `setup.cfg` to `_is_local`, `.resolve().as_uri()` + PID-scoped `.part` cleanup in `_exe.py`, and absolute recipe URLs + badges in `README.md`. Tested |
