## Report quality notes

### round-1-landscape-gemini.md
- Top recommendation (a single `.py` inliner that never extracts to disk) repeats stickytape's failed
  approach and cannot work with native extensions, which the same report says must be extracted.
- Invented history: says tinyBundle "struggled to keep pace with changing wheel metadata
  specifications". No source.
- Invented audience sizes ("2.5 million", "4 million", "500,000 library authors"). No sources.
- Factual errors: cites PEP 515 for entry points (PEP 515 is underscores in numeric literals);
  PEP 665 rejected "2021" (it was Jan 2022); PEP 723 "ratified in 2023" (accepted Jan 2024);
  Nuitka "complex commercial licensing" (Apache-2.0 with an optional paid add-on); pex "tightly
  coupled to Pants" (standalone tool).
- Hypothesis 5 verdict "confirmed" is wrong: minimum-version *checking* exists (vermin).
- Several citations don't support the claims attached to them.

### round-2-evolution-gemini.md
- Its most-cited source, `[4]`, is **round-1-landscape-compass.md** itself (it was attached as
  context). Its Python sections therefore restate round 1 rather than independently confirm it.
- Citation `[3]` is a 2013 Mozilla post about TowTruck, cited for claims about uv.
- Says Bun uses a binary `bun.lockb`; Bun moved to a text `bun.lock` in 2025.
- Repeats "PEP 723 (2023)".
- The ty vs. Pyrefly comparison table (conformance 76% vs 96%, re-check 4.7ms vs 2.38s) has no
  checkable source. Do not repeat these numbers.

### round-1-landscape-compass.md
- Mostly well-sourced. Errors found: PR #12847 status (above); the "someday" maintainer quote is
  unverified. Several toolchain rows are explicitly marked "not re-verified".
- Its central claim — that `__file__`/metadata assumptions break more bundles than native code
  does — is argued, not measured. The gauntlet exists partly to test it.

### round-2-evolution-compass.md
- Could not access the attached round-1 report, so it researched from scratch. Its agreement with
  round 1 is therefore more meaningful than the gemini report's.
- Node type-stripping "stable" version differs between reports (v24.12 vs v25.2); irrelevant here.
- Recommends a self-contained-executable output mode. That reintroduces code signing and
  notarization, the problem that started this project. Treat as out of scope for the core tool.
